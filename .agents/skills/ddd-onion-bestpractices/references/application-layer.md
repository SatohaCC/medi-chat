# Application Layer

ユースケースの実現と処理フローの制御を担う層。

## 1. 責務・制約
- **責務**: ユースケースの進行制御（オーケストレーション）、ドメインオブジェクト呼び出し、トランザクション境界の設定。
- **制約**: ドメイン層のみに依存。自身にビジネスルールを持たず、ドメインオブジェクトへ委譲する。

## 2. 構成要素
1. **Application Service (Use Case)**: ユースケースをメソッドとして実装（1実行＝1トランザクション）。
2. **DTO (Data Transfer Object)**: 境界を越えてデータを引き渡すためのロジックを持たないデータ構造。

## 3. 典型的な処理フロー
```text
1. 取得: Repository経由で既存の Entity を取得（または生成）
2. 実行: Entity のドメインメソッドを呼び出し（状態変更・ロジック実行）
3. 永続化: Repository 経由で変更された Entity を保存
4. 返却: 実行結果を DTO 等に変換して呼出元へ返却
```

## 4. Domain Service との比較
| 項目 | Application Service | Domain Service |
| :--- | :--- | :--- |
| **役割** | ユースケース（手順・シナリオ）の進行 | 複数オブジェクトにまたがるビジネスルール |
| **依存** | Repository Interface / 外部サービス | 外部非依存（ドメインオブジェクトのみ） |
