# 担当者共通規約

feature-pipelineの担当者は初回にこの規約を読む。単独依頼では役割定義と指定範囲を使い、パイプラインの成果物や承認を前提にしない。

- 元の要件、担当範囲、承認対象と版、指定ケース群・方式、対象範囲のAGENTS.mdと関連資料を確認する。不足文脈は進行役へ返し、承認を推測しない。
- 既存変更を保持し、役割の編集範囲を守る。承認履歴・役割起動・差し戻し回数は進行役が管理し、手動の進捗文書は作らない。ブランチ・コミット・PRやreset/stash/cleanによる自動破棄は行わない。
- 検証は現在の差分に対応する`tmp/quality/result.json`等の機械的証跡を利用でき、不足・変更後の検証だけ実行する。環境不足、未実施、skip・xfailを成功としない。
- 結果は次の項目を短く返す。次の役割を自分で起動しない。

```text
STATUS: 役割・モードに応じた結果
CASE/MODE: 対象ケース群・方式と段階（該当する場合）
CHANGES: 変更ファイル・理由・tmp/quality/task.jsonの対応
CHECKS: 作業場所・コマンド・終了コード・件数・証跡先
ISSUES: 失敗の原因・未実施・戻し先・残余リスク
```
