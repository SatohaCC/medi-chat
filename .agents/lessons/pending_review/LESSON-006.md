## 本文を読むトリガー条件

XML取り込みの保存・回復、原本と構造化データの保存先、Composition Rootの許可ルートを変更する場合。

## 適用する条件／適用しない条件

初期登録原本を参照するSQLite世代へWebから追加登録する構成に適用する。独立したパーサーだけの検証には適用しない。

## 観察した失敗と証拠

`Stored import is inconsistent`の修正と再試行テスト後、ユーザーの実取り込みで`Published file path is unsafe`が発生した。設定済み構造化ディレクトリの兄弟に原本があると起動時に推測しており、実際の初期登録原本のルートと一致しなかった。

## 原因

- 確認済み: 保存先が異なる初期登録原本を含む状態でのHTTP追加取り込みを前回は検証していなかった。
- 未確認: 最初の登録失敗を引き起こした操作の詳細は確定していない。

## 次回の具体的な確認手順

1. 設定済みの原本・構造化データ・取り込み保存先と、DBの所有ルートを比較する。
2. 原本を別配置した初期登録後に、実Composition Rootを使うHTTP追加登録を実行する。
3. 新旧文書が検索世代に残り、既存原本が変わらず、失敗後の同一XML再試行も成功することを確認する。

## 対策の検証

- `backend/tests/integration/test_import_original_directory.py`: 別配置した初期原本を保持し、HTTP追加登録が201、healthの文書件数が2になることを確認した。
- `backend/tests/infrastructure/config/test_import_settings.py`と合わせて5 passed。
