# 添付文書の原文保持と大項目単位の保存

## 入力形式と共通モデル

`AttachmentDecoder` は入力を共通の `AttachmentDocument` に変換する境界で、PMDA XML は `PmdaXmlDecoder` が担当する。別の入力形式を追加する場合も、XMLタグやXMLパーサーをDomain/Applicationへ持ち込まず、この境界にアダプターを追加する。検索索引への投影は `application/indexing/queries/services/attachment_projection.py` が担当する。

`AttachmentSection` は項目番号、標準項目名 (`title`)、原文見出し (`header`)、自身の本文 (`body`)、子項目 (`children`) を区別する。`header` は原文にあるときだけ設定し、欠損時は `None` とする。短い本文から推定しない。本文内の原文見出しは `AttachmentParagraph.is_heading` で区別する。

大項目10は10.1・10.2を子として所有する。子自身の本文・表・参照を親本文へ書き込まず、検索用の投影を作る段階で1件にまとめる。共通モデルの生成・投影にXMLは必要ない。

各本文ブロックの `context.source_order` は文書全体での出現順を表す。大項目へまとめるときもこの順序を使い、親本文→子項目→親本文の並びを保持する。異なる項目を挟む表行は結合しない。順序を指定しない共通モデルは、項目階層と各本文内の順序を使用する。

## XMLからの変換規則

- 原本XMLと画像は従来どおり別途保持する。原本のXMLパス、属性、テキスト、末尾テキスト、コメント、処理命令は原本ツリーに保持する。
- `Header` がなければ見出しを補わない。`Detail` は長さにかかわらず本文として扱う。Itemの子は出現順に読み取り、離れた兄弟Detailを先行結合しない。
- 汎用表の先頭行・セル結合から列見出しを推定しない。セルテキスト、位置、縦横の結合、明示された製品参照を保持する。
- XSDの `TblCaption`、`SimpTblHead`、`SimpleTable`、`SimpTblFoot` の順序と原文を保持する。`SimpTblHead` は列名行とは別の表前置き要素である。
- 相互作用など型付きXMLのフィールドに対する標準列名は、既存の共通定義から得る。原文の `Header` とは区別する。
- `numberContinued` の真値はXSDのboolean表現 `true` と `1` を受け付ける。原文内の参照先番号は大項目へ丸めない。

## 保存・検索契約

新規変換の `document.json` は `medi-chat.pmda-prescription-xml.v2`。`sections` のトップレベルには大項目を置き、子項目は `children` に置く。`section_index` は出典を引くための全番号の平坦な索引として保持する。`title` は標準項目名であり、原文見出しを示すのは `header` と原本ツリーである。

`search_units.jsonl` と登録世代の検索データは大項目ごとに1件。登録ブロックの `context.section` に元の項目番号・標準名を保持し、`is_heading` は原文見出しにのみ付ける。表示用の標準項目ラベルは原文Headerとは別に描画する。検索データは `medi-chat.pmda-sections.v4` だけを受け付ける。旧JSON・旧ブロックの互換読み取りや、欠けた見出しを読み取り時に修復する経路は持たない。

検索条件10.1は大項目10のデータと対応する。項目の一致は番号区切りを尊重し、保存されたブロックの所属番号を照合する。要求された子項目が実在しない場合は取得しない。1と10、10.1と10.2は直接一致させない。大項目10を返すときは、10.1と10.2の区別を内容内に保持する。

変換器バージョンは `medi-chat.pmda-import.v2`。既存の保存原物・索引はこの変更では書き換えない。旧形式は拒否する。旧SQLite移行CLI・検証器・stamp例外は削除し、原本から新しい保存先と空DBへ再生成・再登録する。Alembicによる新規DBのスキーマ作成は維持する。

## 検証範囲

受入テストは原文Headerの有無、本文順序、汎用表の非推定、セル結合、子項目と参照先の保持、XMLに依存しないモデル生成、実SQLiteへの登録と再読込、SQL/世代検索の両経路を対象にする。実データ7件の回帰では原本ツリー全項目とメタデータを従来の保存原物と照合する。

XSD適合性は内容保持とは別の検証である。2026-10-18の調査では、提供された `package_insert-XML.xsd` と `PMDA-xml-lang.xsd` を.NETのXmlSchemaSetでコンパイルし、ローカル原本7件を警告・エラー0件で検証した。実行時インポートにXSD検証は追加していない。PMDAの画面表示、実ブラウザー、外部LLMとの照合はこの検証に含まれない。
