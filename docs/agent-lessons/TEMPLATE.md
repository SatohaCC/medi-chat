# LESSON-NNN: 失敗を識別できる短い題名

- 状態: pending_review
- 作成日: YYYY-MM-DD
- 最終確認日: YYYY-MM-DD（未確認なら未確認）
- 承認者・承認日・承認の参照: 未承認
- 更新案の場合の対象: なし／承認済み本文への相対リンク
- 統合先・廃止理由: なし

## 本文を読むトリガー条件

対象パス、変更する契約、作業内容、エラーの特徴を具体的に記載する。INDEXにはこの条件を載せる。

## 適用する条件／適用しない条件

バージョン・実行環境・前提と、この対策を使うべきでないケースを記載する。

## 観察した失敗と証拠

期待した動作、実際の動作、影響を記載する。ログは必要な部分だけを引用し、事実を確認できる相対リンク・コマンド・終了コードなどを添える。

## 次回の具体的な確認手順

作業前・エラー後・完了前のどこで、何を調べ、どの結果を確認するかを記載する。単なる注意喚起で終わらせない。

## 対策の検証

- 検証方法と成功・失敗の判定条件:
- 実施結果・検証した層・対象差分:
- 未実施・環境不足・skip/xfail:
- 回帰テスト・lint・CI／既存規約へのリンク（未導入なら未導入）:

## 次の関連作業での評価

参照されたか、失敗を検出できたか、誤適用がなかったかを証拠とともに記載する。未評価なら未評価とする。
